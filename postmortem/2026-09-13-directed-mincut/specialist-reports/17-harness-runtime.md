## 5. Concrete runtime fixes

1. **Checkpoint file that survives compaction.** Add `STATE.md` (≤ 1–2 pages: current frontier, the one open primitive, top 3 candidate next steps, last 3 dead ends with lemma IDs, unread audit items) to the permitted file layout in INITIAL_PROMPT.md; make the compaction and resume prompts (author_critic.yaml:166–176) say "read STATE.md first, then only the nodes it lists"; have the harness send a "checkpoint STATE.md now" steer when `last.inputTokens` (already parsed at workflow_runner.py:1320–1321) crosses ~140k, i.e. before Codex's auto-compaction. Evidence: the 9 recoveries each re-read INITIAL_PROMPT + index + AUDITS + 3–12 node files, context regrew to 80–120k in ~10 min, and the 16:39 index omission followed compaction #2. Cost: ~1–2k output tokens per checkpoint, minutes per hour; saves an estimated 20–30% of root time.

2. **Lower the compaction ceiling; drop `body_after_prefix`.** Remove or override `model_auto_compact_token_limit_scope="body_after_prefix"` (workflow_runner.py:216–221) so the root compacts at ~120k rather than 190–230k, and rely on fix 1 to make compaction cheap. Evidence: 165–230k contexts, 23–28M root input tokens per 2-hour segment, quota exhausted after 5.8 h, the fatal compaction at 229k. Cost: more, shorter compactions (each ~2 min of block time); expected ~40% fewer input tokens per hour (inferred).

3. **Cap record growth and separate "recovery" text from "detail".** Require a fixed-size abstract at the top of every node and lemma (the index's "concise result" column already exists; enforce ≤ 40 words) and put all "Detailed work" appendices below a marker that recovery is told not to read; cap node files (e.g. 25 KB) and force splitting. Evidence: PROVED.md 904 KB, A055/A001 84 KB, ≈60 KB of AUDITS re-read 7 times, three subagents spent ~30 min (16:06–16:55) rewriting openings to satisfy the format rules. Cost: near zero; risk of hiding detail is handled by keeping it in the file.

4. **Periodic fresh-eyes solver, isolated from the records.** At every audit batch (or every 60 min of author time) spawn one subagent, preferably a different model (research_audit.yaml already wires claude-fable and kimi-k3), that receives ONLY the statement plus STATE.md's one-page frontier, is forbidden to read APPROACHES/ or PROVED.md, and must return a complete candidate algorithm using the simplest primitives it can (max-flow, min-cost flow, classical combinatorial theorems) with a self-assessed gap list; the root must record a verdict on it in STATE.md. Evidence: only 20 of 125 subagent results were new content, 12 of them in the first 40 minutes of open-ended mandates; zero searches or records touch Edmonds' branchings/rounding/arborescence polytope; the frontier fixed at 15:10:37 was never reframed. Cost: one extra thread for ~20–30 min per cycle, roughly 5–10% of tokens.

5. **Budget alarms and quota-aware pacing.** In the tokenUsage handler (workflow_runner.py:1320–1321) accumulate tokens per hour across root and subagent threads (use all `thread/tokenUsage/updated` events, not only root), emit a status line, and throttle automatically (e.g. drop from 3 persistent subagents to 1, or force a checkpoint+pause) when spend exceeds a configured rate; count auditor models on the same provider (Audit-1 = gpt-6-astra) against the same budget and schedule audits accordingly. Evidence: ≈268M input tokens in 5.8 h ended a 168-h job with no warning in control_events.txt. Cost: trivial code.

6. **Short-lived subagents and re-anchoring.** Replace two-hour persistent subagent threads with one-task spawns (spawn, return, terminate), or at minimum send the same re-anchor steer to subagent threadIds on their compactions instead of discarding non-root messages (workflow_runner.py:1279–1281). Evidence: 21 un-anchored subagent compactions; 12–31M input tokens per subagent thread per segment; results were 78% verification/writing that do not need thread continuity. Cost: none; reduces tokens.

7. **Turn hygiene.** Make the author end its turn at least every ~30 min (the YAML `continuation` prompt at author_critic.yaml:160–165 already exists for this) so pauses, audits, checkpoints and partial-output flushes happen at turn boundaries. Evidence: turn lengths 9/17/38/34/13, 28/40/51, 113 min; the 17:00:06 pause and the 22:06 quota error both interrupted mid-turn; no cache-usage or partial-output update after 20:13. Cost: none.

8. **Search-import guard (light).** Before any node adopts machinery found by search (dynamic SCC, Laplacian solvers, MCMC samplers, Hessian sparsification), require a one-line STATE.md entry "simpler primitive X fails because Y". Evidence: the 18:20–19:49 and 21:01–22:05 search bursts produced 13 nodes, two of which are lower bounds against the imported machinery itself. Cost: none.
