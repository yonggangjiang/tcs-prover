## 3. Critic and LaTeX writer

Critic: one root `codex exec` at critic effort with `--enable multi_agent` (yaml:28) and a prompt telling the model to "spawn multiple fresh independent subagents" (yaml:136–137); the number, effort and lifetime of those subagents are model-chosen and inherit ultra. `_bounded_request_settings` (HEAD 2121–2126) gives the whole call **900 s and one attempt**; a timeout discards every token spent and fails the workflow (structured() raises at 930–945). The subagent reports live only in the critic's context, so nothing is checkpointed if the call dies. The runner already has a cheaper-and-more-rigorous path that is not wired: `_parallel_requests` (HEAD 2129–2165) runs N explicit structured audits from a YAML `parallel:` block with per-audit checkpointing (`critic-audits.json`, HEAD 760–905) and `CRITIC_AUDIT_TIMEOUT_SECONDS=1800` (HEAD 80). Recommended configuration: `parallel: {items: [4 foci], effort: xhigh, features: []}` with the shared prefix (statement + proof) first and the focus last so the four requests share the prompt cache (xean does this deliberately, pi-roles.ts:333), then one root critic at ultra that only adjudicates and repairs; timeout 3600 s. Independence is by construction (fresh processes, no channel), cost is bounded (no idle 100k-token root context while waiting), and a crash resumes from the checkpoint. Writer: one structured call, `multi_agent` and `shell_tool` disabled, 25 KB `final` prompt; measured 4.6 min and ≈0.30% of weekly quota. Keep it single-call; set timeout 1800 s and cap the compile/repair loop at 3.

## 4. Token accounting and budget alarm

At HEAD, `goal_session` reads `thread/tokenUsage/updated` only after `if not is_root(message): continue` (1280), stores `last_usage` (1314–1315) and reports it once per root turn via `emit_cache_usage` (1318–1320); subagent usage (70% of tokens) and every `account/rateLimits/updated` event (2,770 of them, carrying `primary.usedPercent`, `windowDurationMins`, `resetsAt`) are dropped. The working tree now adds `meter_update` before the root filter (per-thread base+current with counter-reset handling, `token_budget`/`output_token_budget`, `token-usage.json`, a status line every 600 s). Two fixes and one addition: (a) `meter["calls"] += 1` counts the 542 duplicate emissions; skip an event whose `total` triple equals the previous one for that thread (that is how the 2,228-call figure reconciles); (b) the meter is token-based, while the binding constraint is the provider's weekly percentage — add `quota_percent_limit` (default 60) and `quota_rate_alarm` (default 20 %/h) fed from `account/rateLimits/updated`, which also captures the gpt auditor and any other Codex use on the account; on breach steer "write the PLAN checkpoint and end the turn", then use the existing pause path (`thread/goal/set paused` + `turn/interrupt`, HEAD 1150–1158) so the run pauses resumably instead of dying mid-compaction as this one did (error at 22:06:42 "Error running remote compact task: You've hit your usage limit"); (c) persist `usedPercent` and `resetsAt` in job-settings.json so a resume can refuse to start below a configured headroom. Optionally pass `goals.max_goal_token_budget` as a provider-side backstop; the runner already maps `budgetLimited` to a stop (1333).

## 5. Per-auditor time box and digest

HEAD `run_auditor` polls `while process.poll() is None: consume(); if cancelled.wait(0.2): _stop(process)` (audits.py 256–259) with no deadline; the batch waits on `as_completed(futures)` (496) for the slowest auditor, and the author stays paused. The working tree adds a batch-level `threading.Timer(timeout_seconds(config))` that sets every cancel event (audits.py ~647–655, `timeoutMinutes: 25`) and `write_digest` after the reports are saved (~715, parsing VERDICT/DIRECTION/PREMISE lines into `audit-digest.md`; the records tool serves it via `records.py audits`). Two refinements: make the deadline per auditor inside `run_auditor` (start time next to `pending, report, actual_model = ...`) so a slow auditor's partial stdout is still harvested and the timeout is reported per slot rather than as a batch cancel; and run the auditors on a read-only snapshot (copy of INITIAL_PROMPT.md, APPROACHES/, PROVED.md: 2.4 MB) without pausing the author — the pause cost 61 min (14.6% of wall time) and, because auditors are read-only, only the digest delivery needs the turn boundary.

## 6. Waste in the runner itself, and the records rule

- Transcript emission is not a model cost: 47,910 `item/agentMessage/delta`, 8,254 `summaryTextDelta`, 4,201 `summaryPartAdded`, 426 `outputDelta` records = 65 MB. Keep completed items; make deltas opt-in (`--set transcript_deltas=false` in `record()`, HEAD 1130–1133). The UI trace retention and the 8-file `pause.json` copies are likewise I/O only.
- The 900 s single-attempt timeout (2125) is the one place the runner can throw away a large ultra call; the LaTeX repair loop is the one place it can loop without bound.
- `emit_cache_usage` is root-only and per turn; superseded by the meter.
- Records rule vs helper CLI: the author prompt says "do not create new files or change the file structure"; `tools/records.py` lives in the repo, not the run directory, and only reads, so calling it (`python3 "$TCS_PROVER_TOOLS/records.py" overview|node A012 --section objective|lemma L034|grep|audits`, 16 KB cap per call, says what it cut) does not conflict. Two gaps: `_cap` truncates at 16 KB but a `--lines 0 --section all` request on A001 (83 KB) still injects 16 KB, so pair it with `tool_output_token_limit`; and `overview` prints every index row and lemma title (60 nodes, 73 lemmas ≈ 10 KB) on every compaction recovery — add `--active` to list ACTIVE/BLOCKED nodes only. The digest file `audit-digest.md` in the run root is a controller-owned file, so the prompt's "controller manages AUDITS/ and audit_history/" sentence should name it too (the working-tree prompt does).

## 7. What xean does that transfers

- Fresh-context turns (docs/philosophy.md §4: an Explorer turn receives the task, guidance, note metadata and selected support texts, never earlier transcripts): the direct analogue is single-task subagents with a written brief and the fresh-eyes solver, both now in the working-tree prompts; the runner-side enforcement (`agents.*` keys, §2) is what is still missing.
- Hard caps on a continuation: `contextBudgetTokens = 400_000`, `maxResponses = 4` (packages/solve/pi-roles.ts:188–189; README "Explorer continuation"); tcs-prover's analogue is `compaction_tokens`/`checkpoint_tokens` plus a per-turn call cap (root turns reached 350 calls / 113 min) delivered as a steer.
- `replayReasoning: false` (pi-roles.ts:76, 590): later requests omit earlier reasoning items, "the provider bills only the visible transcript". No equivalent key exists in the Codex 0.153.4 binary; Codex replays encrypted reasoning. Not adoptable.
- `maxSourceWebActions` default 16 per source call (pi-roles.ts:109): a runner-side counter of `webSearch` items per thread with a steer at the cap would enforce the prompt's 6/hour.
- Role/effort mix (examples/settings-mixed.json: explorer max, coordinator low, correctness/requirements high, reconstruction max; profile-review.json: gpt-6-astra xhigh for the independent review): map to author ultra, subagents xhigh by task, auditors xhigh, writer xhigh.
- Prompt diet (docs/role-runner.md: PASS explanations omitted, shared texts once, `window` 100k chars for verifiers; verifier prompts ordered so the cacheable prefix comes first, pi-roles.ts:333): digest instead of 115 KB of reports, `records.py lemma` statements-first, and the critic parallel prompt ordering in §3.
- Accounting (packages/solve/accounting.ts: `derivePiSpend` → `measuredCostUsd`, unaccounted calls listed; SPEC "each operation is counted once"): `token-usage.json` plus dedupe plus the quota events, and `view_transcript.py --usage`.
