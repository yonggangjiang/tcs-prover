          Running jobs

          All jobs share the rate and usage limits of the same CLI logins and API keys. The jobs of a folder run beyond this limit wait in a queue and start in order as running jobs finish or pause; automatic retries wait for a free slot too. TCS Prover starts queued jobs and retries at most one every 2 seconds. A job you start or resume yourself always starts.

          Web search cutoff

          Choose unrestricted search, a historical cutoff, or no web-search tools.

          Optional

          Enter -1 to disable all web-search tools, or an exact UTC timestamp including seconds and Z. Historical search returns only verified captures strictly before that time. The choice stays fixed after the job starts.

          The model's native web search is enabled without a date restriction.

          Limits and logging

          Default 2. An unchanged PASS proceeds at once; an edited PASS repeats until the limit, then a last review that cannot edit must pass the proof unchanged. Unfixable issues return to the author and reset the count.

          How many independent critics the critic starts as its subagents on each proof version (1-10); it weighs their reports and makes the decision.

          0 means unlimited. A limit pauses the proof author, which then writes a progress summary; the critic and LaTeX steps always finish. You can change the limit while the job runs or is paused.

          Fast applies to Codex CLI models only and uses credits at a higher rate. Claude CLI and API models always run at standard speed.

          Public reasoning summaries for every stage (Concise is recommended); Anthropic-format API models show none. Private chain-of-thought is never displayed or saved.
